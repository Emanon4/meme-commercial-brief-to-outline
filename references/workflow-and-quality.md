# 工作流与质量门槛

## 工作对象

这个 Skill 只处理商单的策略前策：理解 Brief、扩展可选创意、锁定内容结构。语言成稿、排版和数字人导演化使用不同的质量标准，留给下游独立处理。

原始 Brief 是最高约束和不可改写的证据。Brief Lock 只记录经过人工确认的执行理解，不能产生高于原文的新要求。创意方向和大纲必须沿着 `Bxx` 回到客户原文，`Dxx` 记录人做出的确认与取舍。

## 状态与人工闸门

| 当前状态 | 允许执行 | 必须停止的位置 |
| --- | --- | --- |
| `brief_draft` | 拆解原文，并按选题调研维度给出探索性创意 | 等待用户修正解读并选择方向，不得生成大纲 |
| `brief_locked` | 保留或继续扩展已有灵感 | 不得替用户选择方向 |
| `creative_draft` | 深化、比较方向并给出推荐 | 等待用户选择、组合或否决 |
| `creative_selected` | 把选定方向收敛为大纲 | 不得同时写口播成稿 |
| `outline_draft` | 检查结构和 Brief 覆盖 | 等待用户确认 `OL-vN` |
| `outline_locked` | 生成下游交接包 | 不得自动调用下游 Skill |
| `ready_for_director` | 供用户手动交给数字人导演 | 下游不得静默改变上游锁 |

原始 Brief 的精读与探索性灵感池构成同一个首轮交付。用户明确修正解读、确认版本、选择方向并要求继续时，可以生成下一个阶段草案，但仍需在 Outline Lock 前停止。

## 人与模型的职责

模型负责完整拆解、暴露矛盾、按选题调研维度扩展创意、验证映射，并给出有理由的推荐。人负责确认 Brief 解读、判断创意品位、选择取舍和批准结构。校验脚本只检查可确定的结构条件，不对审美打分。

模型不得因为用户要求「精准」就隐藏不确定性。Brief 中没有写出的意图只能作为推断；推断缺少文本依据时改为待确认项。

## 版本规则

- Brief Lock 使用 `BL-v1`、`BL-v2`。
- Creative Decision 使用 `CD-v1`、`CD-v2`。
- Outline Lock 使用 `OL-v1`、`OL-v2`。
- 修改已锁定内容时创建新版本，并保留旧版本的确认记录。
- 只修改当前阶段的措辞或排版且不改变含义时，可以留在同一草案；改变目标、硬约束、创意机制或段落功能时必须升版。
- 所有人工确认、选择和否决使用稳定的 `Dxx` 留痕；同一决定被补充说明时保留编号，作出新取舍时新增编号。

## 质量检查

Brief 阶段检查每条解释是否有原文依据，关键冲突是否被提出，目标受众、期望变化、品牌作用和成功标准是否可以从客户材料中得到支持。执行解读不能改写产品卖点，也不能提前把某个创意写成客户要求。

创意阶段先检查是否完成群众基础、情绪浓度、认知反差、社交货币、话题张力、价值获得的逐维度发散，再检查完整方向能否从重点维度推出并服从同一份 Brief。删掉品牌后创意仍原样成立，说明品牌只是贴片；只有标题、场景或开头不同，说明方向同质。

大纲阶段检查每段是否引起明确的认知或情绪变化，证据是否承担证明责任，品牌出现是否由内容关系推动。删除某段后结构和 Brief 覆盖都不受影响时，删除或合并该段。

交接阶段检查下游所需字段是否齐全，所有版本是否已经确认，关键未决项是否为「无」。若仍需客户决定，不得把档案标为 `ready_for_director`。
